## Подготовка

Нужны PowerShell и Docker Desktop. Установка Python в Windows не требуется.

1. Развернуть RustFS, используя результаты домашнего задания № 2; контейнер должен называться `rustfs-lab2`, S3 должен быть доступен на `localhost:9000`.
2. Загрузить свой файл `it_vacancies_2024.csv` в бакет `hh-lake`. Исходный файл размером 847619384 байта не включён в Git.
3. В окружении работающего RustFS должны быть `RUSTFS_ACCESS_KEY` и `RUSTFS_SECRET_KEY`. Скрипты сами получают их из контейнера, передают Docker через окружение и восстанавливают прежние значения процесса PowerShell. Значения секретов не печатаются. Не включать трассировку PowerShell при работе с секретами.
4. В PowerShell перейти в этот каталог: `Set-Location .\devops-lab` из корня репозитория.

Первый запуск SQL собирает образ `hh-lab-duckdb:1.4.3` из `Dockerfile.duckdb`; при сборке нужен интернет. Затем образ используется повторно. Источник из Docker доступен по `host.docker.internal:9000`.

## Полные команды

```powershell
Set-Location .\devops-lab

& .\run.ps1 -Inspect
& .\run.ps1
& .\run-duckdb.ps1
& .\run-analysis.ps1
& .\run-regions.ps1
& .\run-benchmark.ps1
```

`run-duckdb.ps1` по умолчанию сверяется с исходным префиксом эталонного запуска. На новом хранилище после собственного MapReduce передать выведенный им префикс:

```powershell
& .\run-duckdb.ps1 -ReferencePrefix 'mapreduce/devops/ИМЯ_ВАШЕГО_ЗАПУСКА'
```

При самостоятельном воспроизведении профилирования на новом бакете передать такой же префикс собственного манифеста, предварительно сверенного с DuckDB:

```powershell
& .\run-benchmark.ps1 -ReferencePrefix 'mapreduce/devops/ИМЯ_ВАШЕГО_ЗАПУСКА'
```

Стандартные контрольные числа относятся к данному исходному CSV и данному варианту.

Каждый запуск создаёт новый локальный каталог результатов и новый префикс S3; сохранённые материалы отчёта не перезаписываются.

## Методика

- Вакансии: точное равенство роли `DevOps-инженер`, после очистки пробелов и регистра. Единица наблюдения - строка CSV, не уникальный `vacancy_id`.
- Навыки: разделение по `;`, нормализация пробелов/регистра, устранение дубликатов в одной вакансии. Сочетания неупорядоченные. MapReduce использует Python `casefold`, SQL - `lower`; эквивалентность на этом наборе подтверждена полным сравнением всех результатов, а не предполагается для произвольного Unicode.
- Зарплата: RUR/RUB, `gross=false`, середина вилки либо одна указанная граница. Некорректные/неположительные/перевёрнутые вилки исключаются. 762 зарплаты, из них 564 вакансии имеют навыки; медиана 210000 руб.
- База пары - более частый навык, база тройки - более частая входящая пара. Частота базы берётся по всей выборке роли, при равенстве - лексикографический выбор. База включает вакансии расширенного сочетания. Рейтинги требуют минимум 20 зарплат у сочетания и базы.
- Региональная доля считается от **всех** вакансий роли в регионе, включая записи без навыков. Во всех регионах сравниваются также одинаковые глобальные топы, включая нули.
- Разница медиан описывает связь, а не причинное действие навыка. Опыт, работодатели, регион и удалённая работа в общем зарплатном рейтинге не контролируются.

## Профилирование

| Метод | Попыток | Медиана времени, с | Медиана пика RSS, МиБ |
| --- | ---: | ---: | ---: |
| MapReduce | 3 | 74.214 | 79.25 |
| DuckDB | 3 | 79.729 | 966.52 |

Граница времени: создание свежего Python-процесса - его завершение. Включены импорты, подключение, чтение S3, агрегации, сортировка и локальная запись CSV. RSS за всю жизнь процесса измерен Linux `wait4`; память RustFS и контроллера исключена. Сборка/запуск Docker, сверка и загрузка в S3 находятся вне замера. Контейнер ограничен 2 CPU и 2 ГиБ RAM; DuckDB использует до 2 потоков, MapReduce однопоточный.

Кеши не очищались. Разброс времени велик, диапазоны перекрываются; устойчивое превосходство по времени тремя попытками не доказано. Медиана пиков RSS у MapReduce примерно в 12.2 раза меньше. Старый диагностический SQL-замер 39.436 с имеет другие границы и не используется в этом сравнении.

В реальный mapper введена ошибка на 100-й выбранной вакансии. Код завершения 1, CSV/manifest не появились локально и в выделенном S3-префиксе. Отдельный полный перезапуск без ошибки дал код 0, точное совпадение и успешное обратное чтение выходов из S3. Автоматические повторные попытки, checkpoint и распределённая замена узлов не заявляются. Отказ и восстановление не входят в шесть сравнительных замеров.

## Повторная сборка PDF

Из этого каталога, без Python в Windows:

```powershell
docker build -f Dockerfile.report -t hh-lab-report .
docker run --rm --mount "type=bind,source=$((Get-Location).Path),target=/app" hh-lab-report python build_report.py
```

Новая копия появится в `output/pdf/hh-devops-report.pdf`. Закоммиченный отчёт находится в `report/hh-devops-report.pdf`. Генератор использует сохранённые результаты фиксированных запусков и шрифты с поддержкой кириллицы; внешние секреты для сборки отчёта не нужны. Исходный проверенный PDF сформирован с Arial; при повторной сборке в Linux используется DejaVu Sans, поэтому переносы могут отличаться.

Бонусная оптимизация с отдельными замерами «до/после» не заявляется.
